# 开发计划

- 版本：v0.1（2026-09-21）
- 假设：1 名全栈开发（或 1 后端 + 1 前端），每周 5 个有效工作日
- 示例排期基线：2026-09-28 开工；已计入国庆假期约 1 周顺延，**MVP 目标发布：2026-11-27 前后**

## 1. 总体路线

```
MVP(约9周) ──► v1.1(4周) ──► v1.2(4周) ──► v2.0(8~10周)
 核心可用      运维增强      体验/集成      HR同步与迁移
```

| 版本 | 主题 | 主要内容 | 预估工期 |
| --- | --- | --- | --- |
| MVP | 核心可用 | 建库向导、目录树、人员/组、Schema 动态表单、Excel 导入导出、LAM 并存、自助改密、审计 | 8 周 + 1 周缓冲 |
| v1.1 | 运维增强 | 批量操作、多目录档案、忘记密码、Excel 大文件与列映射、ppolicy 完整化、审计检索 | 4 周 |
| v1.2 | 体验与集成 | 拖拽移动、只读角色、变更通知（群机器人）、内置手册、API 化雏形 | 4 周 |
| v2.0 | HR 同步与迁移 | 通用同步引擎、飞书/企微/钉钉导入、第三方 LDAP 迁移、LDAPS/证书增强、AD 兼容 | 8~10 周 |

## 3. 关键路径与依赖

1. **subschema 解析（M0 spike → M2 落地）** 是动态表单的前置，也是"自定义 schema 兼容"的根，风险最高，故放在最早验证；
2. **计划引擎（M3）** 是 Excel 与 v2.0 同步的公共内核，M3 完成时必须按抽象接口交付，不许写成 Excel 专用逻辑；
3. **并存回归（M4）** 依赖 M1/M2 的功能面；一旦建立就进入 CI 常跑，后续所有版本不得破坏；
4. 改密入口（M4）不依赖其他模块，若 M4 挤压可提前至 M3 并行。

### v2.0（约 2027-04 起，8~10 周）重点：HR 同步与迁移

核心是**通用同步引擎**（R12.4）：

```
connector（飞书/企微/钉钉/LDAP/Excel）
   → 字段映射（源字段 → LDAP 属性，可配置）
   → diff 计划（新建/更新/禁用/报错，人工预览确认）
   → 执行 + 报告（复用 MVP 计划引擎内核）
```

| 内容 | 对应需求 | 预估 |
| --- | --- | --- |
| 通用同步引擎抽象与实现 | R12.4 | 2 周 |
| 飞书导入（部门+人员，手动全量/增量） | R12.1 | 2 周 |

| AD 深度兼容（独立 adapter：LDAPS、unicodePwd、组类型） | R12.7 | 2 周 |

> 说明：飞书/企微/钉钉均需企业自建应用与通讯录权限，**审批有周期，v2.0 启动时第一件事是提交三个平台的权限申请**。

## 5. 风险与对策

| # | 风险 | 影响 | 对策 |
| --- | --- | --- | --- |
| 1 | Excel 字段映射千差万别，企业各有自有表头 | 导入功能口碑 | MVP 固定中文模板字段保底；自定义列映射进 v1.1；模板附填写说明与示例行 |
| 2 | 与 LAM 并存的长尾冲突场景 | 数据安全口碑（最高优先级风险） | 属性级修改纪律 + entryCSN 冲突检测 + 回归用例库持续积累；任何破坏用例即阻塞发布 |
| 3 | ppolicy 在 2.4/2.5/2.6 间行为差异 | 改密提示不准 | 建立 2.4/2.5/2.6 测试矩阵，错误码映射表覆盖测试 |
| 4 | 飞书等开放平台权限申请周期不可控 | v2.0 排期 | 启动即申请；先做引擎与钉钉（门槛最低）验证模式 |
| 5 | 单人开发，进度波动 | 发布延期 | 预定义裁剪顺序，延期时依次砍：专家模式高级编辑 → 结构模板多选项 → 性能优化目标放宽；**核心 CRUD / Excel / 改密 / 并存四条主线不裁** |
| 6 | 安全问题（改密入口被刷、凭据泄露） | 安全事故 | 强制 HTTPS + 限流 + 凭据加密进 MVP；发布前安全检查清单逐项过 |
| 7 | "零基础用户"实测仍觉难 | 产品目标未达成 | M4 完成后找 2~3 名非运维同事实测场景 A/D，按卡点修正文案与向导 |

## 6. 工程约定

- 分支：`main` 保持可发布，功能走 `feature/*`，里程碑打 tag；
- 测试：核心逻辑（schema 解析、计划计算、错误映射）单元测试；testcontainers 起 OpenLDAP 做集成测试；并存回归与四场景 e2e 进 CI；
- 提交信息与文档中文为主；每个里程碑结束时同步更新文档再进入下一阶段。
