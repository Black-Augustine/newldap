## 1. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 后端语言 | Go 1.22+ | 单二进制分发、并发模型适合多目录连接、运维工具生态成熟 |
| LDAP 客户端 | `go-ldap/ldap` v3 | 成熟，支持分页控件、modrdn、StartTLS/LDAPS、ppolicy 响应控件 |
| Excel | `excelize/v2` | xlsx 读写、流式解析（v1.1 大文件复用） |
| 前端 | Vue 3 + TypeScript + Vite | 团队熟悉度与生态 |
| UI 组件 | Element Plus | 国人操作习惯的基石：左树右表、抽屉表单、步骤条向导全部现成 |
| 状态管理 | Pinia | 常规选择 |
| 数据存储 | **无**（仅本地配置文件 + 审计日志文件） | "目录即真相"原则的直接体现 |

## 3. 后端模块划分

```
cmd/server            # 入口
internal/
  config/             # 配置加载、环境变量预配置（LDAP_*）映射到连接档案
  ldapclient/         # 连接池、连接档案管理（加密落盘）、rootDSE 探测、分页搜索封装
  schema/             # subschema 解析 → objectClass/属性/语法内存模型
  directory/          # 树浏览、条目 CRUD、modrdn 移动、entryCSN 冲突检测
  people/             # 人员领域（简单模式字段 ↔ LDAP 属性映射、账号禁用）
  group/              # 组领域（场景化建组、成员维护、反向视图）
  planexec/           # 计划引擎：diff 计算 → 预览 → 执行 → 报告（Excel/v2 同步共用）
  excel/              # 模板定义、解析、生成（依赖 planexec）
  selfservice/        # 自助改密（bind 验证、ppolicy 解析、限流）
  auth/               # 管理台会话（登录=bind、超时、CSRF）
  audit/              # JSONL 审计日志（按天滚动）
  api/                # REST 路由与 DTO
web/                  # Vue 3 前端（构建产物内嵌进 Go 二进制）
```

## 4. 关键设计决策

### D1 概念映射（简单模式）

| 界面概念 | LDAP 实现 | 说明 |
| --- | --- | --- |
| 部门 | `organizationalUnit` | 任意层级嵌套，RDN 用 `ou` |
| 人员 | `inetOrgPerson`；勾选"Linux 登录"时附加 `posixAccount` | posixAccount 的 uidNumber/gidNumber 从可配置号段自动分配（v1.1 支持对接已有分配器） |
| 用户组（权限场景） | `groupOfNames` | 成员引用 DN |
| 用户组（Linux 登录场景） | `posixGroup` | 成员可引用 uid |

RDN 属性（uid / cn）与各场景 objectClass 组合做成可配置模板，默认值开箱即用，专家可改。

### D2 Schema 感知与动态表单

- 连接建立后按需读取 `cn=Subschema`，解析 `objectClasses`、`attributeTypes` 得到内存模型；
- 表单生成规则：MUST 属性 → 必填；MAY 属性 → 折叠的"更多属性"；单值/多值 → 单控件/标签组；
- 语法 → 控件映射表：`directoryString`→文本、`telephoneNumber`→电话、`generalizedTime`→日期时间、`boolean`→开关、`JPEGPhoto`/二进制→文件上传、`userPassword`→密码框（只写）；
- 该机制保证"服务器加载了什么 schema 就能管理什么"（R5.4），飞书等导入的字段映射（v2）也基于此模型。

### D3 非破坏性修改纪律（LAM 并存的根基）

- 一切编辑走**属性级 Modify**（对具体属性做 add/delete/replace），**绝不整条条目 Replace**；
- 不认识的属性不动；本工具编辑界面只提交用户实际改过的字段；
- 删除条目前先读全量做预览确认；
- 默认不写入任何私有 objectClass / 标记属性（如确需软删除标记等能力，使用标准辅助 objectClass 且默认关闭）。

### D4 编辑冲突检测

- 打开编辑页时读取并持有 `entryCSN`；提交时服务端再读一次比对，不一致即拒绝并提示"条目已被其他客户端（如 LAM 或其他管理员）修改，请刷新后重试"；
- 同一 DN 的写操作在服务端按 DN 串行化，缩小竞态窗口；
- 该机制对任何并发来源生效（本工具多会话、LAM、ldapmodify 脚本）。

### D5 计划引擎（Excel 导入与 v2 同步的公共内核）

```
Source(Excel/HR API/LDAP) → Normalize(统一内部模型)
  → Match(按 DN/uid/工号 匹配现有条目)
  → Plan(diff：新建 N / 更新 M / 错误 K，更新含字段级 before→after)
  → 人工预览确认（可剔除行）
  → Execute(逐条执行，策略：遇错中止或跳过继续)
  → Report(成功/失败/跳过明细，可下载)
```

- M3 按此接口实现，Excel 只是第一个 Source；v2 的飞书/企微/钉钉/LDAP 迁移只新增 Source 与字段映射，不改内核；
- 执行产生的每批操作进审计日志（汇总 + 可查明细）。

### D6 密码与账号状态

- **自助改密**：用户 DN + 旧密码 bind 验证 → 属性级 replace `userPassword` → 解析 ppolicy 响应控件，错误码映射为中文文案表（2.4/2.5/2.6 测试矩阵覆盖）；
- **管理员重置**：管理 bind 下 replace `userPassword`；服务端支持 ppolicy 时携带重置标记（下次登录强制修改）；
- **禁用/启用账号**：采用跨客户端可理解的标准做法——优先 `pwdPolicySubentry` 指向禁用策略（若服务端可用），否则以文档明示的约定替换密码哈希前缀（如 `{crypt}!*`），界面始终写明所采用的方式，不发明私有机制。

### D7 会话与凭据安全

- 管理台登录 = bind 校验成功后建立会话（cookie：HttpOnly + SameSite=Strict）；
  CSRF 防护（M1 已实现）：SameSite=Strict 为主防线，写方法另做 Origin/Host 一致性校验（无 Origin 的非浏览器客户端放行）——对纯 JSON API + Cookie 形态，双层防护即可，无需 SPA 侧管理 CSRF token；
- bind 凭据仅存于服务端内存会话中，重启即失效；会话滑动过期（`session_ttl` 可配，默认 30 分钟，M1 已实现并有超时测试）；
- 连接档案中的保存密码用 AES-GCM 加密落盘，密钥来自环境变量 `NEWLDAP_SECRET_KEY`，不与档案同存（M1 已实现并浏览器实测；曾发现密钥源未接线缺陷，已修复为默认直读环境变量）；
- 一切日志输出经过脱敏器，禁止出现密码字段的值（审计与配置文件均有泄漏断言测试）。

### D8 自助改密入口安全

- 非 HTTPS 访问默认 302 到 https 并告警（内网豁免需显式配置）；
- 限流：per-IP + per-账号 失败计数，超限锁定窗口 + 可选验证码；
- 统一错误文案不区分"账号不存在/密码错误"，防枚举。

### D9 审计

- JSONL append-only，按天滚动：`{ts, actor, session, ip, op, dn, detail, result}`；
- 覆盖全部写操作与登录事件；Excel/批量操作记批次汇总并可关联行级报告文件；
- v1.1 增加检索与导出（R11.5）。

### D10 LAM 并存验证自动化

- CI 中 compose 起 OpenLDAP + LAM（官方镜像）+ 本工具；
- 脚本化交替操作用例：LAM 建人 → 本工具改字段 → LAM 验证未丢 → LAM 改字段 → 本工具编辑触发冲突提示 → 双方各自删除/移动 → 断言目录终态；
- 该套用例为发布门禁，任何破坏即阻塞（对应风险 #2）。

## 5. API 概要（REST，`/api/v1`）

```
GET  /healthz                     # 健康检查（含 LDAP 连通性）【已实现】
POST /auth/login | /auth/logout   # bind 校验建会话 / 注销【已实现】
GET  /me                          # 当前身份与 BaseDN【已实现】
GET  /setup/status                # 连接配置状态（未配置→前端进向导）【已实现】
POST /probe                       # rootDSE 探测 + bind 测试 + base 空/存量状态【已实现】
POST /setup/profile               # 保存连接档案（密码 AES-GCM 落盘，保存前真实 bind 验证）【已实现】
GET  /tree?base=                  # 树一层懒加载（含 childCount）【已实现】
GET  /entry?dn=                   # 条目详情（含 entryCSN）【已实现】
POST /entry                       # 新建（dn/objectClass/attrs；RDN 自动补齐）【已实现】
PUT  /entry                       # 属性级修改（携带 expectedCSN 冲突检测，409）【已实现】
POST /entry/move-preview          # 移动前预览（新 DN + 随迁条目数）【已实现】
POST /entry/move                  # 移动/改名（modrdn）【已实现】
GET  /entry/delete-preview?dn=    # 删除影响面（子孙计数 + 清单样例）【已实现】
POST /entry/delete                # 删除（非空需 cascade=true，否则 409 not-empty）【已实现】
GET  /search?base=&q=|&filter=&limit=&offset=  # 子树搜索（q 关键字 / 专家 filter）【已实现】
GET  /schema                      # 解析后的 objectClasses 摘要【已实现】
POST /selfservice/password        # 自助改密（独立限流）【M4】
POST /imports/excel               # 上传→解析→返回 Plan【M3】
POST /imports/excel/{planId}/execute / GET report【M3】
GET  /exports/excel?base=         # 【M3】
GET  /audit                       # 审计查询（v1.1）
```

> 注：草案期的 `/connection/*`、`/entries/*` 前缀在实现中定为 `/setup/*`、`/entry*`；以本表为准。
> 错误码约定：401 未登录；403 CSRF/向导守卫；404 条目不存在；409 `conflict`（entryCSN）/ `not-empty`（删除保护）；5xx 目录服务端错误（中文前缀 + 原始错误）。

细节（分页协议、错误码表、DTO）在实现期以 OpenAPI 维护，此处仅为边界约定。

## 6. 部署形态

### 伴随形态（compose）

```yaml
# 样例结构（正式样例随 MVP 交付）
services:
  openldap:      # osixia/openldap 或 bitnami/openldap，LDAP_PORT 不映射宿主机
  new-ldap:      # 本工具；environment 传入 LDAP_* 预配置；depends_on: condition: service_healthy
  lam:           # 可选，用于并存验证/过渡期双工具
```

### 独立形态

- 单二进制或单镜像 + `config.yaml`（首次通过网页向导生成）；
- 前端静态资源内嵌二进制，单文件分发。

### 构建

- 多阶段构建：node 构建前端 → go 构建二进制（embed 静态资源）→ distroless/scratch 基础镜像；
- 多架构：amd64 / arm64。

## 8. 发布前安全检查清单

1. 改密入口强制 HTTPS 生效，HTTP 访问被拒绝/跳转并有告警日志；
2. `config.yaml` 中无明文密码；`NEWLDAP_SECRET_KEY` 变更后旧档案不可解（有明确报错而非崩溃）；
3. 全量日志与审计抽样检查无明文密码/哈希；
4. CSRF / 会话超时 / 登录爆破限流生效；
5. 容器以非 root 运行；镜像扫描无高危 CVE；
6. 审计日志覆盖清单核对：登录、全部写操作、导入批次、改密（不记密码值）。
