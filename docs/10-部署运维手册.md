# 部署运维手册

适用版本：v1.x（单二进制，前端内嵌） ｜ 更新：2026-09-23

本文档覆盖三种部署形态、生产环境注意事项、升级流程、备份与排错。示例主机：192.168.233.132（Ubuntu + Docker Compose）。

---

## 1. 形态选择

| 形态 | 适用 | 入口 |
| --- | --- | --- |
| 演示 / 开发 | 本地体验、二次开发 | `./newldap-server --mock --addr :8080`（内置替身目录，零依赖） |
| 伴随部署（样例） | 新建目录环境一键起栈 | `cd deploy && docker compose up -d`（OpenLDAP + NewLDAP；LDAP 端口不暴露宿主机） |
| 生产部署 | 已有/新建 OpenLDAP 的正式环境 | `deploy/docker-compose.prod.yml`（三件套 + 二进制镜像） |

## 2. 生产部署（compose 三件套）

### 2.1 构建与上传

```bash
# 本地交叉编译（静态二进制，前端已内嵌）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags "-s -w" -o deploy/newldap-server ./cmd/server

# 上传到目标机
scp deploy/newldap-server  deploy/docker-compose.prod.yml  deploy/Dockerfile.binary \
    deploy/schema-newldap.ldif  deploy/seed.ldif  deploy/run-tests.sh  user@host:~/newldap-deploy/
```

### 2.2 compose 要点（docker-compose.prod.yml）

- `openldap`：osixia/openldap:1.5.0，数据落 named volume（openldap-data / openldap-config）
- `newldap`：`build: .`（Dockerfile.binary：alpine + 静态二进制），端口 `18080:8080`
- `phpldapadmin`：8081，与 NewLDAP 共存验证用（NEWLDAP_PLDA_URL 指向它）
- 环境变量：`LDAP_URL / LDAP_BIND_DN / LDAP_BIND_PASSWORD / LDAP_BASE_DN / NEWLDAP_ADDR / NEWLDAP_PLDA_URL`

### 2.3 真实 OpenLDAP 踩坑清单（务必先读）

1. **osixia 容器内端口固定 389**（不是示例中的 1389）；宿主机映射随意。
2. **默认 ACL 禁匿名查询**：健康检查必须带 `-D admin -w 密码`，否则容器永远 unhealthy。
3. 改过环境变量后必须 `docker compose down -v` 清卷重来（首启引导不会重跑）。
4. **自定义属性需先注入 schema**：树的部门排序要 `ouOrder` 属性 → 先执行
   `docker compose exec openldap ldapadd -Y EXTERNAL -H ldapi:// -f /path/schema-newldap.ldif`，
   部门条目自动带上辅助类 `newldapOUExtras`（NewLDAP 界面创建的部门会自动附加）。
5. 宿主机端口冲突：8080 常被占用（示例机被邮件服务占用），NewLDAP 用 **18080**。
6. 对接只读账号（帮助中心创建）用 `organizationalRole + simpleSecurityObject`，**标准 schema，无需注入**。

### 2.4 测试数据与冒烟

- `seed.ldif`：5 部门（含中文名/排序）、15 人员（密码 Passw0rd!）、3 组
- `run-tests.sh`：**29 项功能冒烟**（登录/树/搜索/建人/uid 查重/改名/组/自助改密/entryCSN 409/密码不泄漏/禁用启用/phpLDAPadmin）
  - 注意：组加成员接口须用嵌套 `changes:{add,remove}` 结构（旧扁平结构会报"没有成员变更"）
  - 基线 15 人；跑前确认无历史测试残留（`uid=zhaomin*`、`test-group`、`tmp-verify` 等）

## 3. 升级流程（热更新，不动目录数据）

```bash
# 本地
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags "-s -w" -o deploy/newldap-server ./cmd/server
scp deploy/newldap-server user@host:~/newldap-deploy/newldap-server

# 目标机
cd ~/newldap-deploy
docker compose build newldap && docker compose up -d newldap
curl -s http://localhost:18080/healthz     # {"status":"ok","ldap":"up"}
bash run-tests.sh                           # 29 项回归
```

前端与后端同二进制内嵌，升级永远只替换这一个文件。OpenLDAP 容器与数据卷不动。

## 4. 备份与恢复

```bash
# 备份（线上目录数据 + 配置）
docker compose exec openldap slapcat -n 0 > config.ldif        # schema/ACL 配置
docker compose exec openldap slapcat -n 1 > data.ldif          # 目录数据

# 恢复：down -v 清卷 → 起新 openldap → ldapadd -Y EXTERNAL 导入两份 LDIF → 起新 ldap
```

审计日志在 NewLDAP 容器内 `NEWLDAP_AUDIT_FILE`（默认 `data/audit.jsonl`）；如需持久化请挂载宿主机目录。

## 5. 日常运维

| 事项 | 做法 |
| --- | --- |
| 健康检查 | `GET /healthz`（含 ldap 状态、mock 标记、PLDA 地址）；compose 已配带认证的 LDAP 探测 |
| 证书 / LDAPS | 独立部署时连接向导选 LDAPS/StartTLS；伴随形态目录在容器网络内，可不加密 |
| 凭据轮换 | 帮助中心创建的对接账号可随时改密/停用（就是普通 LDAP 条目，条目编辑即可） |
| 只读收紧 | 帮助中心「对接指引」底部提供 olcAccess 样例 LDIF（按实际 DN 生成），由运维评估后在 OpenLDAP 执行 |
| 排错入口 | NewLDAP「审计日志」页（谁在何时从哪个 IP 做了什么）；phpLDAPadmin 交叉验证目录真实状态 |

## 6. 常见故障

| 现象 | 原因与处理 |
| --- | --- |
| 登录提示无法连接 | LDAP_URL 不通 / 端口填错（osixia 容器内是 389）；`docker compose ps` 看 openldap 是否 healthy |
| 保存报"服务端 ACL 拒绝" | 正常行为：当前 bind 账号权限不足，换管理员或调整服务端 ACL |
| 保存报 409 冲突 | 他客户端（LAM）先改了同一条目；界面提示刷新即可，不会覆盖他人修改 |
| 树不显示部门排序 | 未注入 schema-newldap.ldif（ouOrder 未定义被真实 OpenLDAP 拒绝） |
| 对接系统搜不到用户 | 见帮助中心 FAQ：Base DN 范围 / 过滤器问题，用「过滤器实验器」先验证 |
| 帮助中心建对接账号 409 | 同名账号已存在（换名或用已有账号）；位置不存在时默认位置会自动建 ou=services |
