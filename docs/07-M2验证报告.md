## 4. M1 遗留复验（本轮关闭）

1. **创建 OU 后自动定位**：原 `locate()` 依赖组件内部 getNode，懒加载树重挂载时序下不可靠。重写为 **DOM 驱动**（逐层按名称找节点元素→点展开图标→最终真实点击选中，与用户点击同路径）。实测：创建"数据智能部"→树自动选中、标题/DN 联动 ✅
2. **重命名实时预览**：实测输入"数据中心"预览即时更新 `ou=数据中心,dc=example,dc=cn` ✅；执行改名后树自动选中新名 ✅

过程中发现并修复的缺陷：

| # | 缺陷 | 修复 |
| --- | --- | --- |
| 1 | `people.Detail` 返回 userPassword（与 M1 搜索泄漏同类，自查测试抓到） | 统一 `directory.StripSensitive`（api/people 同源），Detail 增加只读 `disabled` 布尔 |
| 2 | PersonDrawer 基本信息面板不渲染（模板中 `values[f.name]!` 非空断言等构造触发渲染失败，且 Vue 静默卸载该子树、无 console 痕迹） | 重构为 singleValues/multiValues 分离 + 方法化事件处理器；面板恢复渲染 |
| 3 | schema fixture 缺 person/organizationalPerson 父类，导致继承断言与替身表单不真实 | fixture 与替身 subschema 同步富化（10 objectClass + 14 attributeType），继承链测试生效 |
| 4 | 测试替身迷你 schema 未含 gidNumber 等定义 | 同步补齐（gidNumber/uidNumber INTEGER SINGLE-VALUE 等） |

## 6. 遗留与 M3 输入

1. 专家模式 objectClass 编辑目前是自由多选；M3 可结合 schema 表单模型校验"删除 objectClass 需其 MUST 属性已空"；
2. 多值属性编辑为标签式，大批量值（如组 500 成员）场景应换虚拟列表——归入 v1.1 批量操作；
3. 表单字段暂无"折叠更多属性"分组（schema 字段全量平铺），M3 与 Excel 导入向导一起做信息架构梳理；
4. posixAccount（Linux 登录开关）在原型中有、产品里按计划在 M3/导入向导一并接入（uidNumber 分配器与 gidNumber 同套路）；
5. M3（Excel 导入导出）就绪度：模板/解析/行级校验（M0 spike③）+ 计划 diff 内核（planexec）均已测试通过，只欠执行器与向导 UI。
