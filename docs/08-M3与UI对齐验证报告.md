## 2. M3：Excel 导入导出（R7.1~R7.6）

### 后端

- `internal/importer`：**计划构建**（部门按"全路径"对账目录 OU；人员按工号→uid 匹配 → 新建/更新/错误；缺失部门路径明确报错）与**执行器**（部门自底向上创建；新建人员走 people 领域层并**收集初始密码**；更新做属性级 diff + 部门 modrdn 调动；错误行跳过不中断）。
- API：`GET /api/v1/import/template`（模板下载）、`POST /api/v1/import/parse`（multipart，≤10MB，对账出计划）、`POST /api/v1/import/execute`（执行 + 报告 + 初始密码清单）、`GET /api/v1/export/people`（部门+人员两表导出，**永不含密码**）、`GET /api/v1/audit?limit=`（审计读取，R11.3 提前具备基础版）。
- 审计：import（解析/执行各一条，含汇总数字，无密码值）+ export 事件。

### 前端（ImportView，对齐原型四步流）

模板下载（含填写须知）→ 拖拽上传 → 计划确认（四张统计卡 + 明细表，错误行红色底、可核对第 N 行原因）→ 执行（进度条 + 结果报告 + **初始密码一次性清单**，支持复制转交）+ 导出区（永不包含密码的醒目提示）。

### e2e 验收（TestImportExportFlow）

模板下载 → 清示例行 → 填 2 部门 + 3 人（新建/邮箱错误/更新+调动）→ 解析（部门2 新建1 更新1 错误1）→ 执行（ok=4 skip=1）→ **初始密码真实 bind 验证** → 目录核验（部门已建、张伟改名+调动生效、错误行 dengchao 未创建）→ 导出文件可打开、含新人、断言无 password 字段/值 → 审计含 import 事件。

## 3. 过程中发现并修复的缺陷

| # | 缺陷 | 修复 |
| --- | --- | --- |
| 1 | 计划项的执行数据（personRow/deptPath）为未导出字段，JSON 前端往返后丢失 → 执行时"uid 为空"全部失败（e2e 抓到） | 改为导出字段带 json tag，计划数据随预览原样往返 |
| 2 | 模板示例行被计入计划（部门 +4、工号重复错误 +1） | 行为本身正确；测试改为先清示例行（真实用户会替换示例） |
| 3 | 导航"漂移"疑云（点击导入后 URL 又变回 /people） | 系统性验证四页导航各自稳定——为宿主浏览器截图竞态误报，非产品缺陷 |
