## 二、后端待办（按优先级）

### P1（应修）
- **多级部门导入路径错位** `internal/importer/service.go:164` — 构建 `existingOUPaths` 时把当前条目自己的 ou 值回填到 DN 每个 `ou=` 段，`ou=平台组,ou=技术研发部` 生成键 `平台组/平台组`。Excel 引用真实多级部门路径会报"部门路径不存在"。
- **所属组反查永远为空** `internal/people/service.go:159,167` — 空 base 子树搜索在真实 OpenLDAP 报错且被静默吞掉（mock 替身宽容掩盖）。Service 需带 BaseDN。
- **会话无后台清扫** `internal/auth/session.go` — 过期会话（各持一条已 bind 的 LDAP 连接）只在再次 Get 时回收，反复登录可耗尽连接。需 janitor 定时清扫。
- **管理台登录无限流** `router.go handleLogin` — 可无限暴力尝试，还可能触发 ppolicy 锁定真实账号。可复用 selfservice.RateLimiter。
- **搜索先拉全量再切页** `router.go handleSearch` — PagedSearch 拉全部匹配再内存 offset/limit，大目录下单次搜索内存爆炸。需 maxEntries 提前终止。
- **读取错误一律映射 404** `directory.go Get/Update` — 网络故障/ACL 拒绝被当成"条目不存在"。应区分 LDAP NoSuchObject。

### P2（建议）
- healthz 未认证且每次真实拨号 bind，detail 泄漏内部拓扑 → 加缓存 + 仅本地模式带 detail
- 会话 Cookie 缺 Secure 标志（ForceHTTPS 时）
- 审计 CSV 公式注入（前导 =+-@）与 \r 转义
- 失败写操作不留审计（只有 409/非空两个例外）
- audit ReadLast 全量读内存取尾（大文件 O(n)）→ 尾部反向分块读
- 树 Children N+1 搜索（200 子节点 = 201 次搜索）→ 一次子树搜索归组计数
- schema 解析每请求重做无缓存
- schema.go 畸形行 panic 风险（p.values()[0] 无判空）
- 组名未校验 DN 特殊字符（people 的 uid 有校验，组没有）
- NextGID TOCTOU 并发可重号
- planexec 包无调用方（与 importer 重复实现）→ 删或复用
- import/execute 无条目数上限、不尊重 ctx 取消

## 四、环境备注

内嵌浏览器（自动化测试用）在后台标签页不运行 CSS transition（transitionend 不触发），Vue 的弹窗关闭过渡会挂起——这是测试环境伪影，真实 Chrome/Edge 正常。如需彻底免疫（含 prefers-reduced-motion 用户），可后续评估全局关闭 el-dialog 过渡或升级 Element Plus 版本观察修复。

## 五、总体结论

架构健康：'会话=真实 bind、权限=服务端 ACL、无影子库'主线贯彻一致；entryCSN 乐观锁、属性级修改、敏感属性双侧剥离、AES-GCM 落盘均有真实实现。本次发现的问题集中在两类：(1) 声明的安全不变量没有被系统性强制（P0 #1/#2 都是"设计存在、执行漏了一处"，且被 mock 替身宽容掩盖）；(2) 前端三抽屉组件重复实现导致的散点 bug。最值得投入的三个方向：敏感属性剥离收敛到唯一出口序列化层、会话/连接生命周期治理（清扫+登录限流）、大目录可扩展性（搜索截断+树去 N+1+schema 缓存）。
