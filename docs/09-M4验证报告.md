## 1. R9 员工自助改密

### 后端（internal/selfservice + POST /api/v1/selfservice/password）

- **自 bind 验证**（R9.2）：员工只输入账号(uid)+旧密码——服务端以档案凭据（或匿名）解析 uid→DN，再用「本人 DN+旧密码」真实 bind 验证，最后在**本人连接**上替换自己的 `userPassword`。全程零管理员权限，权限=服务端 ACL。
- **ppolicy 友好翻译**（R9.3）：服务端拒绝（结果码 19/53 + diagnostic）翻译为中文白话——历史重复/强度不足/长度不足/修改太频繁/账号锁定 五类精准文案；客户端另做弱密码前置校验（≥8 位、新旧不同）。
- **限流**（R9.5）：双维度滑动窗口——每账号 5 次/10 分钟、每 IP 10 次/10 分钟；触发后 429 + 友好文案；成功改密清零。
- **防枚举**：账号不存在与密码错误的文案完全一致（"账号或密码错误，请确认后重试"），测试断言两种失败逐字相同。
- **审计**：`op=self-password-change` 记录账号/IP/成败，**绝不落密码值**（测试断言）。
- HTTPS 强制（R9.4）：按架构 D8 应在反向代理层统一 TLS 终结时开启，工具自身保留 `NEWLDAP_FORCE_HTTPS` 设计位；mock/开发模式默认不拦截（部署手册中标注生产要求）。

### 前端（/password 独立页，原型化）

独立轻量入口（不进管理台布局）：账号@域名后缀、当前/新/确认密码、**实时强度条**（弱/中/强）、服务端友好错误条（限流用警示色）、成功态（含"其他设备需重新登录"提示）；设计系统与线性图标与全站一致。

### 测试

- 单测：成功路径（旧密码失效/新密码可 bind）、防枚举文案一致、弱密码拒绝、**账号限流**（3 次失败→第 4 次即使密码正确也被拒；无关账号不受影响；成功清零）、五类策略翻译。
- e2e：改密后旧密码 401/新密码 200；错误文案防枚举一致；连续 5 败→429；审计无密码值。
- 浏览器实测：填表→强度条"强"→真实提交→成功态（mock 目录中密码真实变更）。

## 3. R8.6 与 LAM 并存的自动化回归

新增 e2e `TestLamCoexistence`：以**直连 LDAP 的独立客户端扮演 LAM**（绕过本工具全部 API），六个场景交替读写断言：

1. LAM 建人 → 本工具搜索立即可见（R8.1）
2. 本工具属性级修改 → LAM 侧读到新值，且 **LAM 写入的其他字段原样**（R8.2 非破坏）
3. LAM 先改 → 本工具带旧 entryCSN 提交被 **409 拦截**；刷新重交后**双方修改都保留**（R8.5）
4. LAM modrdn 移动 → 本工具搜索 DN 跟随
5. 本工具删除对 LAM 建的数据同样生效
6. 双方各自建部门 → 树终态同时可见（标准操作无私有状态）

真实 OpenLDAP + LAM GUI 的回归由 CI 以等价语义覆盖（LAM 底层即标准 LDAP 读写，本套锁定的正是线协议不变量；GUI 级留待 CI 环境，见 §5 遗留）。
