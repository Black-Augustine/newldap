# 功能规划：新手引导 · LDAP 教学 · 对接指引

日期：2026-09-23 ｜ 状态：待确认 ｜ 依据：用户提供的 8 张竞品参考截图 + 项目现状盘点

---

## 1. 需求背景与截图洞察

用户诉求：**规划新手引导、LDAP 教学、对接指引（让用户能够快速知道对接堡垒机、零信任等产品时候该填写什么信息）等相关的功能。**

参考截图全部是**消费方视角**的 LDAP 对接配置界面——堡垒机 / 零信任 / IAM 类产品接入 LDAP 目录时的表单。归纳出的通用字段集（这就是"对接指引"要反向解答的答案库）：

| 分类 | 消费方表单字段（截图所见） | 本目录的答案 |
|---|---|---|
| 连接 | 服务器地址、端口、协议(ldap/ldaps)、超时 | 本服务地址:389，ldaps 视部署 |
| 认证 | Bind DN / 绑定账号 / 查询用户 DN、密码 | 对接专用只读账号（本功能可一键创建） |
| 范围 | Base DN / 用户 Base DN / 同步根机构 | `ou=people,<base>` 等真实 DN |
| 用户映射 | 用户筛选器、唯一标识、用户名/姓名/邮箱/部门属性 | `(objectClass=inetOrgPerson)`、entryUUID、uid、cn、mail、ou |
| 组织映射 | 组织架构过滤、外部 ID、组名字段、描述 | `(objectClass=organizationalUnit)`、entryUUID、ou（第二 ou=中文名）、description |
| 组映射 | 安全组/角色过滤、名称、成员、描述 | `(\|(objectClass=groupOfNames)(objectClass=posixGroup))`、cn、member/memberUid |

截图值得借鉴的设计点：
1. **字段级 ❓/ⓘ 悬停帮助**——每个易混淆字段旁有解释（本产品已有 `term()` 同款机制）；
2. **高级设置折叠 +「系统已默认配置缺省值，可按需自行调整」**——新手只需填少数必填项；
3. **连通性测试按钮**——保存前先验证（本功能做成"把凭据交给对方之前先自测"）；
4. **分步页签（基础→用户→机构→组）**——把一个吓人的大表单拆成小步。

**核心洞察：NewLDAP 是目录的"提供方"。对接指引 = 把上表右侧的真实值，按对方产品的表单样式排版好，让管理员逐字复制。**

## 2. 总体设计：一个「帮助中心」，三个板块

不散落做三个入口。侧栏新增第 7 个菜单项 **「帮助中心」**（`/help`，lucide `CircleHelp` 线性图标），内部四个页签：

```
/help?tab=onboard   新手引导   —— 上手任务清单 + 步骤引导
/help?tab=learn     LDAP 教学  —— 概念教程（用本目录真实数据举例）+ 过滤器实验器
/help?tab=connect   对接指引   —— 产品模板 → 真实值配置卡（核心板块）
/help?tab=glossary  术语词典   —— 复用 web/src/utils/ldapDict.ts 全量词条
```

辅助入口：
- 概览「快速开始」卡片末尾新增第 5 步"对接第一个系统 → 去对接指引"；
- 顶栏用户区旁加 `?` 图标按钮直达帮助中心；
- 各页面头部远期（P2）加"本页帮助"。

三条硬约束贯穿设计：**目录即真相**（指引展示的值全部实时来自目录与配置，不落任何影子数据；UI 偏好如"已读引导"只存 localStorage）；**图标全用 lucide 描边**；**与 LAM 并存**（对接指引教的 Bind 账号、过滤器同样适用于任何标准客户端）。

## 3. 板块 A：新手引导（onboard）

### 3.1 上手任务清单（升级现有概览「快速开始」卡）

概览页已有 4 步清单，升级为 6 步，完成态**实时从目录推断**（不存状态）：

| # | 任务 | 完成判定（实时查询） | 动作 |
|---|---|---|---|
| 1 | 连接目录并完成探测 | `setupStatus().configured` | 去 /setup |
| 2 | 搭建组织结构 | 目录中 OU 数 > 1 | 去组织与人员建部门 |
| 3 | 录入首批人员 | inetOrgPerson 数 > 0 | 新建人员 / 去 /import |
| 4 | 创建用户组 | 组数 > 0 | 去用户组 |
| 5 | 体验搜索与树定位 | 人员数 ≥ 5 | 打开组织与人员 |
| 6 | 对接第一个系统 | 引导完成标记 | **去对接指引**（直达 /help?tab=connect） |

全部完成时清单收起为一行"✓ 上手完成"，并弹一次庆祝气泡（仅 localStorage 记忆，不再打扰）。

### 3.2 首次登录引导（coach mark，自研轻量）

首次进入管理台（localStorage `nl.tour.done` 不存在）时，右下角浮出"3 步认识本产品"小卡片（非全屏遮罩，可随时关闭）：
1. 左侧目录树 = 你的 LDAP 目录本身（DIT），点任意节点查看条目；
2. 所有修改都是标准 LDAP 写，LAM/phpLDAPadmin 实时互见；
3. 准备好了？去看「对接指引」，知道堡垒机该填什么。

点"开始演示"进入 **聚光灯导览**：自研 `CoachMark.vue`（绝对定位 4 点高亮 + 遮罩 + 气泡 + 上一步/下一步），依次高亮：目录树 → 新建部门按钮 → 组织与人员菜单 → 顶栏帮助入口。约 5 步，每步一句白话 + 一个 lucide 图标。**不引入第三方 tour 库**（driver.js 等样式不可控且 IAB 环境曾出 transition 问题，自研 3-4 百行足够）。

### 3.3 空状态引导

- 组织与人员：目录为空时，中间区显示大号空态卡（`FolderTree` 线性图标 + "从创建第一个部门开始" + 两个按钮：新建部门 / Excel 导入）；
- 用户组：空态卡"权限组用于授权场景（如 VPN、堡垒机），登录组用于 Linux 登录" + 新建按钮。

（现状部分页面 el-empty 已有，统一为此规格。）

## 4. 板块 B：LDAP 教学中心（learn）

原则：**不用虚构例子，全部用本目录的真实数据教学**——管理员学到的概念直接能对上自己屏幕上看到的东西。

### 4.1 概念教程（卡片式，左侧目录导航 + 右侧内容）

| 课程 | 内容要点 | 互动 |
|---|---|---|
| 目录、条目与 DN | DIT/entry/DN/RDN 拿当前登录者的 DN 现场拆解成 RDN 链 | DN 拆解动画（静态分色即可） |
| objectClass 与 schema | 主类/辅助类、MUST/MAY；点开看本服务器真实 subschema | 「查看本服务器 Schema」跳对象类页 |
| 属性 | 拿一个真实人员条目展示"属性=类型+多值" | 嵌入条目抽屉示意 |
| Bind 与权限 | 会话=真实 bind、权限=服务端 ACL（呼应登录页文案） | — |
| 过滤器语法 | `=` `*` `(&...)` `(\|...)` 常用组合 + 常见错误 | 见 4.2 实验器 |
| 组的两种形态 | groupOfNames(member=DN) vs posixGroup(memberUid=uid) | 对比表 |
| 常见误区 | ①改 uid=改 DN（移动条目）②权限组删最后一个成员会被拒（member MUST）③禁用账号=密码失效而非删除 ④ou 删除需先清空子条目 | 折叠面板 |

每课底部："概念在 NewLDAP 里对应什么"——链接到实际功能位置（如"改 uid → 人员编辑页账号字段"）。

### 4.2 过滤器实验器（教学的核心互动）

页面内嵌一个"试一试"面板：
- 输入框（默认预置 `(objectClass=inetOrgPerson)`）+ 常用片段按钮（`(uid=*)`、`(ou=*)`、`(&(objectClass=inetOrgPerson)(mail=*))` 等）；
- 点「执行」调既有 `searchEntries`（只读、limit=20），下方表格展示命中条目的 DN + cn/uid；
- 服务端报错（过滤器语法错）原样展示并附一句白话解释——**把 LDAP 报错变成教学素材**；
- 侧栏提示：这段过滤器就是对接堡垒机时"用户筛选器"该填的内容 → 按钮直达对接指引。

### 4.3 术语词典

把 `ldapDict.ts` 的 attrCN/attrDesc/classCN/classDesc 汇成可搜索列表（属性/对象类两个 Tab + 搜索框）。现有悬停 `term()` 词典的完整版页面化，零新增数据。

## 5. 板块 C：对接指引中心（connect，本规划重点）

### 5.1 信息架构

```
对接指引 /help?tab=connect
├─ 第 1 步：选对方产品类型（卡片单选）
│    ├─ 堡垒机（JumpServer 类）      ├─ 零信任 / SDP
│    ├─ VPN / 网络设备               ├─ 单点登录（SSO/OIDC-LDAP）
│    └─ 通用 LDAP 客户端（Nginx/Jenkins/GitLab…）
├─ 第 2 步：对接信息卡（按对方表单分组展示真实值，逐行复制）
├─ 第 3 步（可选）：创建对接专用只读账号 + 凭据自测
└─ 底部：对方接入后如何验证 + 常见故障对照表
```

### 5.2 第 1 步：产品模板

模板决定信息卡的字段取舍与文案侧重。P0 内置 5 个模板（纯前端常量，`web/src/utils/integrations.ts`）：

| 模板 | 特有提示 |
|---|---|
| 堡垒机（JumpServer 类） | 用户名属性=uid、用户过滤=inetOrgPerson、用户树=ou=people；JumpServer 用户属性映射表逐项给值 |
| 零信任 / SDP | 强调唯一标识用 entryUUID（人员改部门/改名后身份不丢）；组授权用权限组 |
| VPN / 网络设备 | 多数设备只认简单 bind+单过滤器；提醒设备固件对 ldaps 的支持 |
| 单点登录 | LDAP 直接认证 vs 同步两种模式的取舍白话说明 |
| 通用 LDAP 客户端 | 全字段表（与截图 8 的单页表单对齐），适合"其他产品"兜底 |

每张模板卡片：lucide 线性图标 + 一句话场景说明。

### 5.3 第 2 步：对接信息卡（核心交付物）

按参考截图的分组方式渲染"对方表单 → 你该填的值"：

```
┌─ 连接 ────────────────────────────────────────┐
│ 服务器地址    ldap://<服务器IP>:389   [复制] │  ← 值来源见 5.6
│ Base DN      dc=example,dc=cn             [复制] │  ← me().baseDN 实时
│ 协议/加密    ldap（明文，内网）或 ldaps（636）      │
├─ 认证（Bind 账号）─────────────────────────────┤
│ Bind DN      cn=jumpserver,ou=services,…  [复制] │  ← 5.4 创建后回填
│ 密码         ••••••••                        [复制] │  ← 仅创建当次显示
├─ 用户映射 ─────────────────────────────────────┤
│ 用户筛选器    (objectClass=inetOrgPerson)   [复制] │
│ 用户名属性    uid  ·  唯一标识 entryUUID          │
│ 姓名 cn / 姓 sn / 邮箱 mail / 部门 ou            │
├─ 组织架构映射（若对方支持）─────────────────────┤
│ 组织筛选器    (objectClass=organizationalUnit)   │
│ 部门名 ou · 中文名取第二个 ou 值 · 描述 description│
├─ 用户组映射（若对方支持）───────────────────────┤
│ 组筛选器     (|(objectClass=groupOfNames)…) [复制]│
│ 组名 cn · 成员 member（权限组）/ memberUid（登录组）│
└───────────────────────────────────────────────┘
```

细节：
- 每行左侧标签 + `term()` 悬停解释（与截图的 ❓ 一致，词典词条新增 Bind DN/筛选器等对接词条）；
- 每行右侧独立复制按钮（`Copy` 图标，点击变 `Check` 1.5s）；
- 值全部**实时取自**：`me().baseDN`、`setupStatus().profile`、只读账号创建结果；高级参数（超时/分页）折叠并注明"默认值即可，无需修改"（借鉴截图 5 的折叠文案）；
- 「一键复制全部」按钮：生成纯文本配置清单（字段: 值 逐行），便于微信/工单直接粘贴给对方管理员。

### 5.4 第 3 步：对接专用只读账号（杀手级）

**问题**：对接方绝不该拿 admin 的 DN/密码填进对方系统（截图里那个"Bind DN"字段的存在就是在诱导这件事）。

**方案**（目录即真相，全部是标准 LDAP 写）：
1. 界面输入账号名（默认按模板取名，如 `jumpserver`）+ **选择创建位置**（目录结构由用户约定，不强制）：默认建议 `ou=services,<base>`（不存在时自动创建此 OU），也可选已有任意部门 OU 或直接建在根下；表单下方实时预览最终 DN（`cn=<账号名>,<所选位置>`）；
2. 后端在所选位置下执行标准 Add：`cn=<账号名>` + objectClass `organizationalRole` + `simpleSecurityObject` + 随机 16 位密码；
3. 成功后信息卡 Bind DN 行自动回填、密码**仅此一次**完整显示（目录里存的是哈希，谁也拿不回明文）；
4. **诚实提示**：账号本身的"只读"由 OpenLDAP 服务端 ACL 决定，卡片附一段可复制的 `olcAccess` 样例 LDIF（按实际 DN 生成，让该账号仅可读，无写权），供运维在 OpenLDAP 侧执行——不越权替用户改 ACL；
5. 「凭据自测」按钮：后端用该 DN+密码做一次验证 bind（复用自助改密已有后端逻辑），绿灯后再交给对方——呼应截图的"连通性测试"。

后端新增 3 个端点（`internal/api/m6.go` 或并入现有文件）：

```
GET  /api/v1/integration/info     → 聚合 baseDN、连接 URL、建议账号 OU、过滤器预设（纯实时计算，无存储）
POST /api/v1/integration/bindacct → 创建对接账号（body: name）→ 返回 {dn, password}
POST /api/v1/integration/bindtest → 验证 bind（body: dn, password）→ {ok, code, msg}
```

### 5.5 底部：接入验证与故障对照

- 「对方接入后怎么验证」：3 步（用一名真实测试账号在对方系统登录一次 → 回本系统审计日志看该 bind 的来源记录 → 让对方触发一次用户同步，对比人员数）；
- 常见故障对照表（FAQ 手风琴）：能 bind 但搜不到用户（Base DN 太窄/过滤器不含 objectClass）/ 密码对但登录失败（对方用了 sAMAccountName，本目录应填 uid）/ 同步后部门层级丢失（对方未配组织映射）/ 改密后对方不生效（对方缓存，建议 TTL）。

### 5.6 服务器地址怎么填（唯一需要人工确认的值）

NewLDAP 只知道自己连的目录 URL（多为容器内地址），**不等于对方产品可用的地址**。策略：
- 默认值 = 用浏览器地址 `window.location.hostname` 推断同网段地址（多数内网部署成立）；
- 信息卡顶部一行可编辑的"对外通告地址"输入框（localStorage 记忆），占位提示"对方产品访问得到的目录地址，如 ldap://<服务器IP>:389"；
- 不确定时提示：该地址应填**目录服务器（OpenLDAP）本身**，不是 NewLDAP 的 Web 地址——新手最易混的两点之一，文案必须显式写。

## 7. 分期建议

| 期 | 内容 | 理由 |
|---|---|---|
| **P0（先做，价值最高）** | 帮助中心骨架 + **对接指引全流程**（5 模板/信息卡/只读账号/凭据自测/FAQ）+ 概览清单升级 | 直接回答本次需求的核心痛点"对接时该填什么" |

P0 后端 3 端点均薄封装现有能力，前端约 5 个新文件；无 DB 迁移、无 schema 变更（simpleSecurityObject/organizationalRole 均在标准 schema 中，mock 已含 organizationalRole）。

## 8. 明确不做（范围控制）

- 不做 NewLDAP 侧"对接配置存储"（我们是提供方，不保存消费方配置——那是对方系统的数据）；
- 不做视频/动画教程（维护成本高，卡片+实验器足够）；
- 不引入第三方 tour/引导库；
- 不替用户直接修改 OpenLDAP ACL（只给样例 LDIF，由运维决定执行）；
- 手册定稿仍按既定决策暂缓，本文档不是手册。

## 9. 验收清单（P0）

1. 帮助中心 4 Tab 可达，侧栏/顶栏/概览三入口有效；
