# MVP 范围定义

- 版本：v0.1（2026-09-21）
- 上游文档：[需求清单](01-需求清单.md)（需求编号均指向该文档）

## 1. MVP 目标（一句话）

让一名运维在 30 分钟内，在一台空服务器上用 docker compose 起一套**带中文 Web 管理界面的 OpenLDAP**，完成建库、Excel 批量导入组织架构与人员，并让员工能自助改密码；同时，**已在使用 LAM 的存量环境也能安全接入本工具**，两边的修改互不破坏。

## 2. 验收场景故事（MVP 的四条主线）

### 场景 A：全新部署（伴随形态）

运维拿到一台空服务器 → `docker compose up -d`（OpenLDAP + 本工具）→ 打开网页自动进入建库向导 → 选"LAM 经典结构"模板创建 base DN 与分支 → 下载 Excel 模板，填好 3 级部门、500 名人员 → 导入 → 预览（新建 521 条）→ 执行 → 报告全部成功 → 从同一 compose 里打开 LAM，能看到并继续管理这些数据。

### 场景 B：存量目录 + LAM 共管（独立形态）

企业已有 OpenLDAP 且一直用 LAM 管理 → 独立部署本工具，连接向导填地址与一个独立 bind 账号 → 自动探测到 base DN 直接进管理台 → 修改一名员工的手机号（属性级修改，LAM 里其他字段原样）→ LAM 侧同步修改该员工的职务 → 本工具再次编辑该员工时被冲突检测提示"条目已被他人修改，请刷新"。全程无数据丢失、无报错刷屏。

### 场景 C：独立运维工具（对接第三方 LDAP）

运维用单二进制把工具部署到自己的 workstation → 连接公司另一套 OpenLDAP（非本工具部署的）→ 浏览树、搜人、改组、重置密码，全部能力可用；对无权操作的条目界面置灰并说明。

### 场景 D：员工自助改密码

普通员工记住一个网址 `/password` → 输入自己的账号、旧密码、新密码 → 成功后白话提示；密码太弱/与历史重复时，看到的是"新密码与最近 5 次使用过的密码重复，请换一个"，而不是错误码；连续失败 5 次被限流；任何人对该页面的 HTTP 明文访问被拒绝。

## 4. 范围外（明确排除）

| 排除项 | 原因 | 归属 |
| --- | --- | --- |
| AD 深度兼容（AD 上的改密/写操作） | unicodePwd + LDAPS 适配工作量大，且 MVP 用户群以 OpenLDAP 为主 | v2.0（R12.7） |
| 飞书 / 企微 / 钉钉导入 | 依赖通用同步引擎，先以 Excel 导入满足批量诉求 | v2.0（R12.1~R12.4） |
| 多目录连接档案切换 | 单档案已覆盖 MVP 场景 | v1.1（R1.6） |
| 批量操作（批量禁用/移动/删除） | Excel 导入已覆盖批量建立；批量变更风险高需谨慎设计 | v1.1（R3.7） |
| 忘记密码（邮箱/短信验证码） | 依赖外部 SMTP/短信网关集成 | v1.1（R9.6） |
| Excel 大文件（5 万行）与自定义列映射 | 固定中文模板先满足 95% 场景 | v1.1（R7.7/R7.8） |
| 拖拽移动、动态组、回收站、演示数据、双人复核 | 体验增强项，不影响核心价值 | v1.x ~ v2.x |
| slapd 服务端配置管理 | 产品边界明确不做（只读展示另议） | 不做 |
| 多语言（英文界面） | 中文优先 | v2.x（R12.8） |

## 5. 验收标准（Definition of Done）

1. **部署**：全新服务器上按手册 `docker compose up -d`，5 分钟内（不含镜像拉取）网页可登录；独立部署单二进制 + 连接向导同样可用。
2. **建库向导**：空目录完成 base DN、结构模板（含 LAM 经典结构）、初始管理员创建，结果在 LAM 中立即可见。
3. **Excel**：导入"3 级部门 + 500 人员"样例文件，预览数字准确、执行成功、审计有记录；含错误行的文件能给出"第 N 行 / 错误原因"报告；导出与导入数据一致，导出文件不含任何密码字段。
4. **LAM 并存**：并存回归用例（LAM 8.x 与本工具交替增删改同一目录）全部通过；属性级修改不破坏 LAM 写入的字段；entryCSN 冲突检测生效。
5. **自助改密码**：员工改密成功；ppolicy 三类常见错误（质量不足/历史重复/强制修改）提示准确；连续失败触发限流；HTTP 访问改密入口被拒绝。
6. **性能**：5000 条目目录下树浏览、搜索、翻页流畅无卡顿；1000 行 Excel 导入 ≤ 2 分钟。
7. **安全**：连接档案密码加密落盘；日志与审计中无明文密码；全部写操作在审计日志中可查（操作人/DN/动作/IP/时间）。
8. **文档**：中文部署手册、使用手册、compose 样例（伴随形态 / 独立形态）、Excel 模板随版本发布。

## 6. 交付物

- 多架构 Docker 镜像（amd64 / arm64）与单二进制；
- `docker-compose.yml` 样例两份：伴随形态（OpenLDAP + 本工具 + LAM 用于并存验证）、独立形态；
- Excel 导入模板（.xlsx）；
- 中文部署手册 + 使用手册 + API 概要文档；
- 并存回归测试脚本（进 CI）。

## 7. 人力与工作量假设

- 假设 1 名全栈开发（或 1 后端 + 1 前端配合），按每周 5 个有效工作日估算；
- MVP 总工期约 **8 个开发周 + 1 周假期/缓冲**（详见[开发计划](03-开发计划.md)）；
- 排期以 2026-09-28 开工为示例基线，含国庆假期顺延，目标 2026-11 月下旬发布 MVP。
